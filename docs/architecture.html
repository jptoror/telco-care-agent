Cómo funciona Coni

Coni es la agente de atención de Conecta, una telco ficticia. Explica facturas, diagnostica el internet de la casa, recomienda planes y aplica créditos. Esta página muestra cada pieza, cómo viaja una petición y dónde está cada protección.

Mapa

La arquitectura completa

Todo vive en tu cuenta de AWS, en la región us-east-1, separado de los proyectos de São Paulo. Cada flecha entre servicios va firmada con SigV4 (IAM); no hay llaves ni contraseñas en el código.

Tecnologías

Qué hace cada tecnología y para qué sirve

Para cada pieza: qué es, qué papel cumple en Coni, para qué es buena en general y cuándo conviene otra cosa. Están agrupadas por capa, de arriba hacia abajo en el mapa.

inteligencia El modelo y el agente

Amazon Bedrock

servicio de modelos
Qué es
El servicio de AWS para llamar modelos de lenguaje (Claude, Llama, Nova y otros) por API, sin servidores propios. Se paga por token y se controla con IAM como cualquier otro servicio de AWS.
En Coni
Cada vez que el agente piensa, llama a Bedrock con la API Converse. El rol del runtime solo tiene permiso para invocar modelos de Anthropic.
Bueno para
Empresas que ya están en AWS: los datos no salen de la cuenta, los permisos y la facturación son los mismos, y se puede cambiar de modelo con una variable.
Cuándo no
Cuando necesitas un modelo o una función que solo existe en la API directa del proveedor, o una versión que tu cuenta no tiene habilitada (como pasó con Sonnet 5.5).

Claude Haiku 4.5

LLM
Qué es
El modelo pequeño y rápido de la familia Claude. Entiende instrucciones, decide qué herramienta usar y escribe en español e inglés.
En Coni
Es el "cerebro": lee el mensaje, escoge herramientas, interpreta los resultados y redacta la respuesta. Temperatura 0.2 para que sea estable.
Bueno para
Atención al cliente con mucho volumen: responde en uno a tres segundos y cuesta centavos por conversación.
Cuándo no
Razonamiento largo o casos ambiguos con muchas reglas; ahí conviene un modelo más grande. Por eso las reglas importantes viven en código y no en el modelo.

Strands Agents

SDK Python
Qué es
Un SDK de código abierto de AWS para construir agentes. Corre el ciclo "el modelo pide una herramienta → se ejecuta → se le devuelve el resultado" hasta que el modelo responde.
En Coni
Arma el agente con el prompt, las 14 herramientas MCP y los hooks. Los hooks son el punto donde el código revisa cada llamada antes y después de ejecutarla.
Bueno para
Agentes donde el modelo decide el orden de los pasos, con soporte nativo de MCP, Bedrock y OpenTelemetry.
Cuándo no
Flujos que deben seguir un orden fijo; ahí sirve más un grafo explícito (LangGraph) o simplemente código normal.

plataforma Amazon Bedrock AgentCore

AgentCore Runtime

hosting
Qué es
Hosting serverless para agentes y servidores MCP en contenedores ARM64. Cada sesión corre en su propia microVM aislada y se cobra por el tiempo de uso activo.
En Coni
Hay dos runtimes: el del agente (protocolo HTTP, /invocations) y el del MCP de facturación en Java (protocolo MCP, /mcp).
Bueno para
Poner agentes en producción sin administrar ECS o Kubernetes, con aislamiento por cliente y sesiones largas.
Cuándo no
Si la empresa ya tiene una plataforma propia de contenedores y prefiere operar todo ahí, o si necesita arquitectura x86.

AgentCore Gateway

puerta MCP
Qué es
Un endpoint MCP administrado que convierte Lambdas, APIs REST u OpenAPI en herramientas para agentes, con autenticación centralizada.
En Coni
Expone las 8 herramientas de red y atención. El agente ve un solo servidor MCP; el Gateway decide a cuál Lambda va cada llamada.
Bueno para
Exponer muchos servicios existentes a varios agentes sin reescribirlos y con un solo lugar para permisos y auditoría.
Cuándo no
Si la herramienta ya es un servidor MCP propio y solo la usa un agente: conectarse directo es más simple (como hicimos con Java).

AgentCore Memory

memoria
Qué es
Memoria administrada para agentes: de corto plazo (los eventos de la conversación) y de largo plazo (resúmenes y preferencias extraídos automáticamente).
En Coni
Guarda cada turno por sesión y cliente durante 30 días. Si la microVM se recicla, la conversación se recupera.
Bueno para
Que el agente recuerde el contexto entre turnos y entre días sin montar una base de datos propia.
Cuándo no
Si ya tienes un historial de conversaciones en tu CRM y necesitas que sea la única fuente de verdad.

herramientas Cómo se conecta el agente con los sistemas

MCP (Model Context Protocol)

protocolo
Qué es
Un protocolo abierto para que cualquier agente descubra y llame herramientas de cualquier servidor: tools/list para saber qué hay y tools/call para usarlas.
En Coni
Todo lo que el agente puede hacer pasa por MCP, sobre HTTP en modo stateless. Así el agente no conoce bases de datos ni Lambdas, solo herramientas.
Bueno para
Reutilizar las mismas herramientas en varios agentes y clientes (Claude Desktop, IDEs, otros frameworks) y cambiar la implementación sin tocar el agente.
Cuándo no
Para una función pequeña que solo usa un agente en el mismo proceso: una herramienta local es más simple.

Java 21 · Spring Boot · Spring AI

backend
Qué es
Spring Boot es el framework más usado para servicios en Java. Spring AI agrega piezas de IA; aquí, un servidor MCP en el que cada método con @McpTool se vuelve herramienta.
En Coni
Contiene la lógica de dinero: facturas, comparación con el mes anterior y la política de créditos con BigDecimal, probada con JUnit.
Bueno para
Exponer a agentes un servicio Java que ya existe, como suelen ser los de facturación en una telco, sin reescribirlo en Python.
Cuándo no
Herramientas muy pequeñas: para eso una Lambda en Python arranca más rápido y cuesta menos.

AWS Lambda

funciones
Qué es
Funciones que se ejecutan bajo demanda y se pagan por invocación, sin servidor encendido.
En Coni
Dos funciones Python (network y care) que el Gateway invoca con el nombre de la herramienta.
Bueno para
Herramientas cortas y sin estado: consultas, diagnósticos, crear un ticket.
Cuándo no
Cuando hay estado que debe persistir: una Lambda caliente guarda memoria entre llamadas, que fue justo el bug del módem reiniciado. Ese estado va en una base de datos.

datos Dónde viven los datos

Amazon S3

archivos
Qué es
Almacenamiento de objetos (archivos) barato, durable y prácticamente ilimitado.
En Coni
Guarda los CSV de clientes, facturas, uso, módems y caídas en raw/, y los resultados de Athena, que se borran a los 7 días.
Bueno para
La base de un data lake: guardas archivos una vez y los lees con muchas herramientas distintas.
Cuándo no
Datos que cambian registro por registro a cada rato; S3 guarda archivos completos, no filas.

AWS Glue Data Catalog

catálogo
Qué es
Un catálogo de metadatos: dice que tal carpeta de S3 es una tabla con tales columnas y tal formato.
En Coni
Define la base conecta con 3 tablas (customers, invoices, invoice_lines) sobre los CSV, con un lector que respeta comillas y comas.
Bueno para
Que Athena, Spark, Redshift o QuickSight vean los mismos archivos como tablas, con un solo esquema compartido.
Cuándo no
Si los datos ya están en una base relacional; ahí el esquema lo tiene la propia base. Glue también hace ETL, pero aquí solo usamos el catálogo.

Amazon Athena

SQL sobre S3
Qué es
SQL serverless sobre archivos en S3. No hay base de datos encendida: pagas por los datos que lee cada consulta.
En Coni
El MCP de Java consulta facturas y líneas con consultas parametrizadas (WHERE invoice_id = ?). El workgroup corta cualquier consulta que lea más de 100 MB.
Bueno para
Analítica y consultas sobre grandes volúmenes (historial de facturación, CDRs) sin cargar los datos a otra base.
Cuándo no
Respuestas en milisegundos: cada consulta tarda de uno a varios segundos, y por eso los turnos en AWS tardan más. En producción, la factura del mes iría en una base transaccional o caché.

Amazon DynamoDB

base NoSQL
Qué es
Base clave-valor administrada, con respuestas de pocos milisegundos y cobro por petición.
En Coni
Tabla conecta-credits: cada crédito emitido, con cliente como clave de partición. La política la lee para no acreditar dos veces lo mismo.
Bueno para
Escrituras y lecturas rápidas por clave: estados, órdenes, créditos, sesiones.
Cuándo no
Consultas con joins o filtros libres; para eso está SQL (Athena o una base relacional).

operación Seguridad, despliegue y observabilidad

IAM y SigV4

seguridad
Qué es
IAM define qué puede hacer cada rol. SigV4 es la firma criptográfica que AWS exige en cada petición para saber quién llama.
En Coni
Cada pieza tiene su rol con permisos mínimos. El agente firma con SigV4 sus llamadas MCP al Gateway y al runtime de Java (sigv4.py). No hay llaves ni contraseñas en el código.
Bueno para
Comunicación entre servicios de AWS sin secretos que rotar o filtrar.
Cuándo no
Para identificar al cliente final: ahí va un JWT (por ejemplo, Cognito) que el Runtime y el Gateway también saben validar.

Docker · ECR

contenedores
Qué es
Docker empaqueta la aplicación con todo lo que necesita. ECR es el registro de imágenes de AWS.
En Coni
Dos imágenes ARM64 (agente y MCP de Java) con tag según el contenido. Los repositorios son inmutables y guardan solo las últimas 5.
Bueno para
Que lo que corre en tu Mac sea exactamente lo que corre en AWS.
Cuándo no
Funciones muy pequeñas: las Lambdas se suben como zip, sin contenedor.

Terraform

infraestructura como código
Qué es
Describe la infraestructura en archivos; Terraform compara con lo que existe y crea, cambia o borra lo necesario.
En Coni
Crea unos 45 recursos en us-east-1 y deja intacto São Paulo. deploy.sh es idempotente y destroy borra todo.
Bueno para
Entornos reproducibles, revisables en un pull request y fáciles de destruir.
Cuándo no
Pruebas rápidas de una sola vez en la consola. Aun así, con dinero de por medio conviene tenerlo en código.

OpenTelemetry · ADOT · X-Ray

observabilidad
Qué es
OpenTelemetry es el estándar abierto de trazas. ADOT es la distribución de AWS, que instrumenta Bedrock, MCP y Strands sola. X-Ray con Transaction Search guarda los spans en CloudWatch.
En Coni
Cada turno deja una traza con las llamadas al modelo (y su id), las herramientas MCP, los ciclos del agente y los eventos de Memory. Se ve en CloudWatch, GenAI Observability.
Bueno para
Responder "¿por qué el agente hizo esto?" y "¿dónde se fue el tiempo?" con datos y no con suposiciones.
Cuándo no
Si la empresa usa otro proveedor (Datadog, Grafana): al ser estándar, basta con cambiar el destino del exportador.

Evals · pytest · JUnit

calidad
Qué es
Pruebas unitarias para el código determinista y evaluaciones de conversaciones completas para el agente.
En Coni
16 pruebas unitarias y 12 escenarios que revisan herramientas, argumentos y texto, en local y contra AWS.
Bueno para
Cambiar el prompt, el modelo o el código y saber en minutos si algo se rompió. Así se encontraron los euros y la autocorrección filtrada.
Cuándo no
Las revisiones exactas no juzgan tono ni empatía; para eso se suma un juez con LLM o revisión humana.

    Capa 2 · antes de la herramienta

    Consentimiento

    Política de créditos

    Cómo se comprueba que funciona

    evals/run_evals.py conversa con el agente en 12 escenarios y revisa, sin usar otro LLM, qué herramientas se ejecutaron, con qué argumentos y qué dijo. Corre igual contra el agente local o contra el desplegado con --remote.

    Lo que las pruebas atraparon

    1. Respondía en euros. Decía "49,50 €": el número era correcto y la moneda no. Ahora el prompt fija USD y el verificador rechaza cualquier otra moneda.

    2. La autocorrección se filtraba. Tras un rechazo del verificador le decía al cliente "déjame corregir mi respuesta". La instrucción ahora pide reescribir limpio, y cada evaluación busca esas fugas.

    3. El despliegue destruía los runtimes. La primera fase de deploy.sh aplicaba sin tags de imagen y los recreaba. Ahora crea solo ECR primero; un segundo despliegue sin cambios da 0 modificaciones.

    4. Estado pegado en la Lambda. Un reinicio de módem de una sesión seguía vigente en la siguiente. Ahora expira a los 5 minutos.
